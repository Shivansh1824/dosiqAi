Task: Select potential biomarkers from unmatched lab results that health app users commonly track. Return raw JSON with selected IDs only.

INPUT STRUCTURE:
{
  "id": "unique_id",
  "test_name": "name of test",
  "db_interpretation": "lab interpretation",
  "value": "numeric value with unit"
}

SELECTION LOGIC:
1. Analyze 'test_name' first - Recognize and translate common medical abbreviations (e.g., "Vit" for Vitamin, "HDL" for High-Density Lipoprotein, "B12" for Cobalamin).
2. If test_name is unclear/vague, use 'value' (including UNIT) + 'db_interpretation' for context. 
   - UNIT SENSITIVITY: Use units as clues (e.g., mIU/L often indicates Thyroid/TSH, ng/mL often indicates Vitamin D or Ferritin).
3. Include if: user-friendly, commonly tracked, or has clear health implications.
   - GOLD STANDARD TARGETS: Glucose, Vitamin D, B12, TSH (Thyroid), Ferritin (Iron), LDL/HDL Cholesterol, Albumin, HbA1c.

ALWAYS EXCLUDE:
- Ratios (contains "/" or "Ratio")
- Derived/calculated values (eAG, averages)
- Absolute counts if % version exists in input
- Subjective markers (Color, Odor, Appearance)
- Microscopy (Cells, Casts, Crystals, Bacteria, Yeast)
- Obscure chemicals (Ketones, Nitrite, Urobilinogen, Bile)
- Technical indices users don't understand (MCH, MCHC, RDW, MPV, PDW, MCV)
- Cell differentials (Neutrophils%, Lymphocytes%, Monocytes%, Eosinophils%, Basophils%)
- Redundant tests (PCV when Hb exists, Urea when BUN exists)
- Tests requiring medical expertise to interpret

OUTPUT:
[{ "id": "tr_xxx" }]

CRITICAL: Keep id exactly as input - never modify.

Examples:
- "Hemoglobin" → anemia marker, popular → SELECT
- "Vit D" → abbreviation for Vitamin D → SELECT
- "Unknown X" (value: "10 mIU/L", interp: "Pituitary hormone") → unit and context show TSH → SELECT
- "MCH" → technical, not user-friendly → REJECT
