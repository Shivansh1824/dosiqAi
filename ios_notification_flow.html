1. The Hybrid Architecture

To bypass the 64-notification limit on iOS, we implement a split strategy.

A. Primary Reminder (The Shield)

  • NATIVE Uses RepeatFrequency.DAILY.
  • Cost: 1 Slot per medication (Indefinite).
  • Offline: Works forever.
  • Config: Does NOT change dynamically. Must be cancelled/recreated on edit.

B. Follow-up Reminders (The Rolling Window)

  • MANUAL Scheduled individually via loop.
  • Window: "Today" + Next 3 Days.
  • Refill Trigger: App Open (Foreground) OR Notification Action (Background).
  • Cost: Consumes remaining slots (~50).

2. Database & Data Source

All logic is derived from these fields. NO hardcoding.

TABLE: family_members
  - ios_followup_count (INT): 0, 1, 2, or 3
  - snooze_duration (INT): Minutes (e.g., 5, 10)

TABLE: medicine_schedule
  - scheduled_time (TIME): e.g., "09:00:00"
  - id (UUID): Used for ID generation

Part 2: Follow-ups (The Loop)

// 2. Schedule Follow-ups (Manual Loop)
const followUpCount = familyMember.ios_followup_count; // e.g., 2
const snoozeMins = familyMember.snooze_duration;       // e.g., 5

for (let day = 0; day < 3; day++) { // Next 3 days
  const dateStr = getDateString(day); 
  
  for (let i = 1; i <= followUpCount; i++) {
     
     // DYNAMIC SAFETY VALVE CHECK
     const count = (await notifee.getTriggerNotificationIds()).length;
     if (count >= 63) {
         scheduleRefillReminder(); // "Reminders Low"
         return; // STOP ALL SCHEDULING
     }

     const followUpTime = calculateTime(baseTime, day, i * snoozeMins);
     
     await notifee.createTriggerNotification({
       id: `${scheduleId}_followup_${i}_${dateStr}`, // Deterministic ID
       title: `Missed dose: ${medName}`,
       ios: {
         threadId: `med_${scheduleId}`, // Same group
         interruptionLevel: 'timeSensitive'
       }
     });
  }
}

4. Event Handling (The Cluster Kill)

Logic for notificationEventHandler.ts.

A. Action Press (Taken/Skip)

  • Trigger: User clicks "Taken" action button.
  • Action:
    1. Calculate all potential IDs: [primaryId, f1_today, f2_today...].
    2. Call notifee.removeDeliveredNotifications(withIdentifiers: allIds).
    3. Run Refill Logic (Background Task) to schedule next 3 days.
    4. Result: Clears the specific med stack from Lock Screen & ensures continuity.
  • Safety: Do NOT cancel the *Primary* scheduled ID (Trigger), only the *Displayed* one.

B. Standard Press (App Open)

  • Trigger: User taps body.
  • Action: Open App. Do NOT cancel follow-ups automatically (unless app logic determines med is taken).

5. ID naming Convention (Strict)

  • Primary: {scheduleId}
  • Follow-up: {scheduleId}_followup_{index}_{YYYY-MM-DD}
  • Thread ID: med_{scheduleId}
  • Refill Alert: global_refill_alert
